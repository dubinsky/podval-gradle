= Podval Gradle conventions
:toc:
:toclevels: 3

Shared Gradle setup for Podval (and other) projects: toolchain, Scala 3 flags,
`dependencyUpdates` filters, Maven Central publishing. Not the site-publisher plugin
(that stays in `site-publisher`).

Java binary plugins (`java-gradle-plugin`), same shape as
`org.podval.tools.site-publisher`. Plugin ids:

`org.podval.conventions.settings` (`settings.gradle`)::
Foojay toolchain resolver; `dependencyResolutionManagement { repositories { mavenCentral() } }`.
Does **not** apply `com.gradleup.nmcp.settings` (publishing builds keep that line).
`org.podval.conventions` (`build.gradle`)::
Applies `io.github.ben-manes.versions` and the shared `rejectVersionIf` (non-stable + padded numeric `0.017`).
If `java` is present (covers `java-library` / `scala`): Java 25 toolchain.
If `scala` is present: `-release:25`, `-new-syntax`, `-feature`, `-language:strictEquality`, `-source:future`,
and `scala.scalaVersion` from the `scalaVersion` Gradle property when that property is set.
Does **not** skip `compileJava`.
`org.podval.conventions.publish` (`build.gradle`; libraries and Gradle-plugin projects)::
`javadocJar` from ScalaDoc **before** `withJavadocJar()`; `withSourcesJar()`;
jar `duplicatesStrategy = EXCLUDE` and Implementation-* manifest;
Maven publication POM (SCM, issues, CI, Apache-2.0, developer) and in-memory signing from
`signingKey` / `signingPassword`.
Creates a `library` publication unless `java-gradle-plugin` is applied
(`pluginMaven` + markers already cover the jar).
Sets `gradlePlugin.website` / `vcsUrl` from `gitHubRepository`.

`org.podval.conventions` does not apply `scala` or `java` — the consumer still does.
Markup-only sites (`www.podval.org`, MathWorlds) can apply it without `scala` and still
get versions + toolchain once they have a Java plugin, or skip it and only use
site-publisher + settings.

Maven coordinates (plugin markers on Central; not the Gradle Plugin Portal):

----
id 'org.podval.conventions.settings' version '0.1.0'
id 'org.podval.conventions' version '0.1.0'
id 'org.podval.conventions.publish' version '0.1.0'
----

== Consumer shape

----
// settings.gradle
pluginManagement {
  repositories {
    mavenCentral()
    gradlePluginPortal()
  }
  // String path: a File would call Settings.includeBuild (not a plugin build)
  // and `org.podval.conventions.settings` would not resolve.
  final String conventionsDir =
    providers.gradleProperty('podvalGradleDir').getOrElse('../podval-gradle')
  if (file(conventionsDir).isDirectory() && file("${conventionsDir}/settings.gradle").isFile()) {
    includeBuild conventionsDir
  }
}
plugins {
  id 'org.podval.conventions.settings'
}

// build.gradle
plugins {
  id 'scala'
  id 'org.podval.conventions'
  id 'org.podval.conventions.publish'
}
----

Pin versions on the convention ids once they are on Maven Central (CI has no
composite). Local checkout substitutes, same as site-publisher.

`pluginManagement { repositories { mavenCentral() } }` is already required for
`org.podval.tools.site-publisher` if that plugin is also Central-only.

== Publish extension

POM fields that differ per repo are an extension, not hard-coded Podval:

----
plugins {
  id 'java-library'
  id 'scala'
  id 'maven-publish'
  id 'signing'
  id 'org.podval.conventions'
  id 'org.podval.conventions.publish'
}
podvalPublish {
  gitHubRepository = 'dubinsky/xml'   // required
  name = 'Podval XML'                 // POM <name>; default project.name
  inceptionYear = '2026'
  orgName = 'Podval Group'            // default
  orgUrl = 'https://www.podval.org'   // default
  developerEmail = 'dub@podval.org'   // default
}
----

OpenTorah uses this publish plugin with `orgName = 'Open Torah Project'` /
`developerEmail = 'dub@opentorah.org'`. Do not special-case OpenTorah in the plugin
code. A Gradle-plugin project (`java-gradle-plugin`) still owns `gradlePlugin {
plugins { } }` (id, implementation class, tags).

nmcp (`com.gradleup.nmcp.settings`, `nmcpSettings { centralPortal { … } }`) stays in
the library’s `settings.gradle`. It is already one block and is not used by sites.

Apply `scala` (when used) **before** `org.podval.conventions.publish` so `javadocJar`
is registered from ScalaDoc before `withJavadocJar()` reuses it.

== Local iteration: composite build, not mavenLocal

Same rule as site-publisher README **Dogfooding**: `pluginManagement { includeBuild }`
when the checkout exists; Maven Central when it does not. Do **not** use
`publishToMavenLocal` / `mavenLocal()` to try changes.

== Why this repo, not `dub.podval.org`

`dub.podval.org` is a published notes site (and a site-publisher consumer). Putting
convention plugins there would mean `includeBuild('../dub.podval.org')` from `xml`,
`pulumi`, OpenTorah, MathWorlds — a website composite for build logic.

This repo is only Gradle conventions. Local path next to the other Podval Gradle
projects so `includeBuild('../podval-gradle')` matches `../site-publisher` /
`../xml`.
