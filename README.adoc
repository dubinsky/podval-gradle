= Podval Gradle conventions
:toc:
:toclevels: 3

Shared Gradle setup for Podval (and other) projects: toolchain, Scala 3 flags, `dependencyUpdates` filters, Maven
Central publishing.
Not the site-publisher plugin (that stays in `site-publisher`).

Java binary plugins (`java-gradle-plugin`), same shape as `org.podval.tools.site-publisher`.
Plugin ids:

`org.podval.conventions.settings` (`settings.gradle`)::
Foojay toolchain resolver; `dependencyResolutionManagement { repositories { mavenCentral() } }`.
Applies `io.github.ben-manes.versions.settings` and the shared `rejectVersionIf` (non-stable + padded numeric `0.017`)
on the root `dependencyUpdates` task.
Subprojects contribute partial results and do not get their own `dependencyUpdates` task.
When `gradle.properties` contains `podvalCentral=true`, applies `com.gradleup.nmcp.settings` 1.6.2 and configures
Central Portal `USER_MANAGED` from `mavenCentralUsername` and `mavenCentralPassword`.
`org.podval.conventions` (`build.gradle`)::
Creates the `podval` extension.
If `java` is present (covers `java-library` / `scala`): the Java toolchain `languageVersion` is conventioned to
`podval.jvmLanguageVersion` (default 25).
If `scala` is present: compiler parameters from `podval.scalaCompilerParameters` (`-release:25`, `-new-syntax`,
`-feature`, `-language:strictEquality`, `-source:future`), `scala.scalaVersion` from the `scalaVersion` Gradle property
when that property is set, and `scala.zincVersion` conventioned to `1.12.1`.
Does **not** skip `compileJava`.
Does **not** call `allowJdk25RestrictedAccess()`.
`org.podval.conventions.publish` (`build.gradle`; libraries and Gradle-plugin projects)::
Applies `maven-publish` and `signing`.
`javadocJar` from ScalaDoc **before** `withJavadocJar()`; `withSourcesJar()`; jar `duplicatesStrategy = EXCLUDE` and
Implementation-* manifest; Maven publication POM (SCM, issues, CI, Apache-2.0, developer) and in-memory signing from
`signingKey` / `signingPassword`.
Creates a `library` publication for Java libraries.
Does not create `library` for Gradle plugin projects (`pluginMaven` and marker publications are those coordinates).
Apply `java-gradle-plugin` or `com.gradle.plugin-publish` before this plugin.
Sets `gradlePlugin.website` / `vcsUrl` from `gitHubRepository`.

`org.podval.conventions` does not apply `scala` or `java` — the consumer still does.
Markup-only sites (`www.podval.org`, MathWorlds) can apply it without `scala` and still get the toolchain once they have
a Java plugin, or skip it and only use site-publisher + settings.
Settings already registers `dependencyUpdates`.

Maven coordinates (plugin markers on Central; not the Gradle Plugin Portal):

----
id 'org.podval.conventions.settings' version '0.2.0'
id 'org.podval.conventions' version '0.2.0'
id 'org.podval.conventions.publish' version '0.2.0'
----

This repo pins the last Central release on `org.podval.conventions.settings` and does not `includeBuild` itself.
`org.podval.conventions` and `org.podval.conventions.publish` apply from that same artifact already on the classpath —
do not put a version on those two ids here.
Keep `java-gradle-plugin` / `gradlePlugin { }`.
Publishing builds set `podvalCentral=true`.

== Consumer shape

----
// settings.gradle
pluginManagement {
  repositories {
    mavenCentral()
    gradlePluginPortal()
  }
  // String path: a File would call Settings.includeBuild (not a plugin build)
  // and `org.podval.conventions.settings` would not resolve.
  final String conventionsDir =
    providers.gradleProperty('podvalGradleDir').getOrElse('../podval-gradle')
  if (file(conventionsDir).isDirectory() && file("${conventionsDir}/settings.gradle").isFile()) {
    includeBuild conventionsDir
  }
}
plugins {
  id 'org.podval.conventions.settings' version '0.2.0'
}

// build.gradle
plugins {
  id 'scala'
  id 'org.podval.conventions'
  id 'org.podval.conventions.publish'
}
----

Consumers pin `org.podval.conventions.settings` `0.2.0` so CI works without a composite.
`org.podval.conventions` and `org.podval.conventions.publish` apply from that same artifact already on the classpath.
Local checkout substitutes, same as site-publisher.
Keep the `includeBuild` path a `String`.
Do not replace that snippet with an init script.
`gradlePluginPortal()` stays in `pluginManagement`, because Foojay 1.0.0 and `gradle-versions-plugin` 0.66.0 are not on
Maven Central.

`pluginManagement { repositories { mavenCentral() } }` is already required for `org.podval.tools.site-publisher` if that
plugin is also Central-only.

== Dependency update alerts

`org.podval.conventions.settings` registers `dependencyUpdates`.
`.github/workflows/dependency-updates.yml` runs that task and keeps one GitHub issue, titled "Dependency updates
available", open while the report has a dependency update or a current-channel Gradle update.
A clean report closes that issue.
A Gradle release candidate alone does not open it.

GitHub runs a reusable workflow only when another workflow calls it.
Each repository that wants the alert adds a caller.
Issues must be enabled there, and the caller must grant `contents: read` and `issues: write`.
Pin `<ref>` to a commit or tag that contains this workflow.
The `0.1.0` tag does not.

----
name: Dependency updates
on:
  schedule:
    # Monday 12:00 UTC
    - cron: "0 12 * * 1"
  workflow_dispatch:
permissions:
  contents: read
  issues: write
jobs:
  dependency-updates:
    uses: dubinsky/podval-gradle/.github/workflows/dependency-updates.yml@<ref>
----

This repository calls that file from `.github/workflows/dependency-updates-check.yml` on the same schedule.
The relative `uses` path does not need a tag.

== `podval` extension

`org.podval.conventions` creates `podval`.
Read the JVM language version, add or remove Scala compiler parameters, or opt in to the JDK 25 helper:

----
plugins {
  id 'java-library'
  id 'scala'
  id 'org.podval.conventions'
}

// The extension value. A direct java.toolchain.languageVersion.set is separate.
podval.jvmLanguageVersion.get()

podval {
  jvmLanguageVersion.set(JavaLanguageVersion.of(21))
  scalaCompilerParameters.add('-Xfatal-warnings')
  scalaCompilerParameters.remove('-source:future')
  allowJdk25RestrictedAccess()
}
----

`scalaCompilerParameters` starts as `-release:25`, `-new-syntax`, `-feature`, `-language:strictEquality`, and
`-source:future`.
Changing `jvmLanguageVersion` does not rewrite that list.
Edit the list in the build script.
`allowJdk25RestrictedAccess()` adds `--enable-native-access=ALL-UNNAMED` and `--sun-misc-unsafe-memory-access=allow` to
this project's `JavaExec` and `Test` tasks.
Calling it again does not duplicate an argument that is already present.
The plugin does not call it.

When `scala` is applied, `scala.zincVersion` is conventioned to `1.12.1` (Gradle 9.8.x conventions `1.12.0`).
A build-script assignment still wins, whether it runs before or after this plugin.
Delete local `scala.zincVersion` pins after upgrading to this version.
`scala.scalaVersion` still comes from the `scalaVersion` Gradle property when that property is set.
There is no default Scala version.

The Java toolchain `languageVersion` is conventioned to `podval.jvmLanguageVersion` (default 25).
A prior or later `java.toolchain.languageVersion.set` wins for compilation and does not write back into the extension.

== Publish extension

POM fields that differ per repo are an extension, not hard-coded Podval:

----
plugins {
  id 'java-library'
  id 'scala'
  id 'org.podval.conventions'
  id 'org.podval.conventions.publish'
}
podvalPublish {
  gitHubRepository = 'dubinsky/xml'   // required
  name = 'Podval XML'                 // POM <name>; default project.name
  inceptionYear = '2026'
  orgName = 'Podval Group'            // default
  orgUrl = 'https://www.podval.org'   // default
  developerEmail = 'dub@podval.org'   // default
}
----

OpenTorah uses this publish plugin with `orgName = 'Open Torah Project'` / `developerEmail = 'dub@opentorah.org'`.
Do not special-case OpenTorah in the plugin code.
A Gradle-plugin project (`java-gradle-plugin`) still owns `gradlePlugin { plugins { } }` (id, implementation class,
tags).

Central publishing is `podvalCentral=true` in `gradle.properties`.
The settings plugin then applies nmcp 1.6.2 with `publishingType = USER_MANAGED`.
Sites leave the property unset.

Apply `scala` (when used) **before** `org.podval.conventions.publish` so `javadocJar` is registered from ScalaDoc before
`withJavadocJar()` reuses it.
Apply `java-gradle-plugin` or `com.gradle.plugin-publish` **before** `org.podval.conventions.publish`.
`library` is created for Java libraries and is not created for Gradle plugin projects.
`pluginMaven` and marker publications are the plugin coordinates.

== Local iteration: composite build, not mavenLocal

Same rule as site-publisher README **Dogfooding**: `pluginManagement { includeBuild }` when the checkout exists; Maven
Central when it does not.
Do **not** use `publishToMavenLocal` / `mavenLocal()` to try changes.

== Why this repo, not `dub.podval.org`

`dub.podval.org` is a published notes site (and a site-publisher consumer).
Putting convention plugins there would mean `includeBuild('../dub.podval.org')` from `xml`, `pulumi`, OpenTorah,
MathWorlds — a website composite for build logic.

This repo is only Gradle conventions.
Local path next to the other Podval Gradle projects so `includeBuild('../podval-gradle')` matches `../site-publisher` /
`../xml`.
